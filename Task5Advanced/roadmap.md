# Стратегический роадмап внедрения Data Mesh

## 1. Ключевые роли в Data Mesh

### 1 Роли уровня домена (Domain-level)

| Роль                           | Ответственность                                                                                                                              | Кто назначается                                         | Необходимые компетенции                                                                                    |
|--------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------|------------------------------------------------------------------------------------------------------------|
| **Data Product Owner**         | • Владелец данных домена<br>• Определяет, какие данные публиковать<br>• Отвечает за качество данных и SLA<br>• Приоритизирует задачи команды | Руководитель бизнес-направления (главврач, финдиректор) | • Глубокое понимание бизнес-процессов домена<br>• Навыки product management<br>• Понимание ценности данных |
| **Data Engineer (Domain)**     | • Реализует пайплайны данных в домене<br>• Настраивает публикацию событий<br>• Обеспечивает качество данных                                  | Инженер данных в команде домена                         | • Kafka, SQL, Python<br>• Понимание DDD<br>• ETL/ELT процессы                                              |
| **Domain Expert**              | • Описывает бизнес-сущности<br>• Участвует в создании событий<br>• Тестирует качество данных                                                 | Бизнес-аналитик домена                                  | • Знание предметной области<br>• Коммуникация                                                              |
| **Software Engineer (Domain)** | • Развивает операционные сервисы<br>• Продюсирует события из кода                                                                            | Разработчик домена                                      | • Микросервисы, Kafka<br>• Язык домена (Java/Go/Python)                                                    |

### 2 Роли платформенного уровня (Platform-level)

| Роль                       | Ответственность                                                                                              | Количество | Необходимые компетенции                                     |
|----------------------------|--------------------------------------------------------------------------------------------------------------|------------|-------------------------------------------------------------|
| **Platform Lead**          | • Отвечает за платформу данных в целом<br>• Координирует развитие инфраструктуры                             | 1          | • Архитектура данных, Kafka, Cloud<br>• Лидерские качества  |
| **Data Platform Engineer** | • Развивает платформенные сервисы (Kafka, Catalog)<br>• Обеспечивает SLA платформы<br>• Консультирует домены | 3-4        | • Kafka, Kubernetes, Cloud<br>• IaC, мониторинг             |
| **Data Architect**         | • Разрабатывает стандарты и практики<br>• Помогает с дизайном событий<br>• Проводит ревью                    | 1-2        | • DDD, Event Storming<br>• Data Mesh, моделирование         |
| **Data Governance Lead**   | • Федеративное управление<br>• Стандарты безопасности<br>• Compliance с регуляторами                         | 1          | • Управление данными<br>• Знание регуляторов (152-ФЗ, GDPR) |
| **BI Analyst (Federated)** | • Работает с данными из разных доменов<br>• Создает кросс-доменные отчеты<br>• Обучает бизнес-пользователей  | 2-3        | • Power BI, SQL<br>• Понимание бизнеса                      |

### 3 Роли потребителей (Consumer-level)

| Роль                     | Ответственность                            | Кто                           |
|--------------------------|--------------------------------------------|-------------------------------|
| **Self-service BI User** | Самостоятельно строит отчеты на портале    | Бизнес-аналитик, руководитель |
| **Data Scientist**       | Использует данные для обучения моделей     | Специалист по ИИ              |
| **Partner Developer**    | Интегрируется с данными компании через API | Разработчик партнера          |

## 2. Этапы внедрения Data Mesh

```
2026                            2027                            2028
├── Q2 ── Q3 ── Q4 ── Q1 ── Q2 ── Q3 ── Q4 ── Q1 ── Q2 ── Q3 ── Q4
│                                                                  
│  Этап 1: Подготовка и пилот        Этап 2: Масштабирование      Этап 3: Целевое состояние
│  (0-6 месяцев)                     (6-18 месяцев)               (18-36 месяцев)
│                                                                  
│  • Выбор пилотных доменов           • Подключение всех доменов    • Полный отказ от DWH
│  • Формирование команд              • Кросс-доменные отчеты       • Монетизация данных
│  • Запуск событий                   • Географическая экспансия    • Самообслуживание
```

## 3. Этап 1: Подготовка и пилот (0-6 месяцев)

**Цели этапа**

| Цель                               | Критерий успеха                         | Срок      |
|------------------------------------|-----------------------------------------|-----------|
| Выбрать 2 пилотных домена          | Домены согласованы                      | Месяц 1   |
| Сформировать платформенную команду | 4 человека наняты/назначены             | Месяц 2   |
| Развернуть базовую платформу       | Kafka, Schema Registry работают         | Месяц 3   |
| Запустить первые события           | 3-5 событий от каждого пилотного домена | Месяц 4-5 |
| Демонстрация первых результатов    | Рабочий прототип портала                | Месяц 6   |

**Рекомендуемые пилотные домены:**

| Домен                  | Обоснование                                                                                  | Data Product Owner   | Команда                           |
|------------------------|----------------------------------------------------------------------------------------------|----------------------|-----------------------------------|
| **Пациентский поток**  | • Понятные границы<br>• Быстрая ценность (загрузка врачей)<br>• Не зависит от других доменов | Руководитель клиники | 1 Data Engineer + 1 Domain Expert |
| **Финансовые расчеты** | • Четкие метрики<br>• Высокий интерес от бизнеса<br>• Поддержка от финтех-команды            | Финдиректор          | 1 Data Engineer + 1 аналитик      |

**Ключевые активности**

| Активность                         | Ответственный                    | Результат                                    |
|------------------------------------|----------------------------------|----------------------------------------------|
| **Создание платформенной команды** | CTO/CIO                          | Platform Lead, 3 Platform Engineer           |
| **Выбор и настройка платформы**    | Platform Team                    | Kafka, Schema Registry, Data Catalog (пилот) |
| **Обучение команд**                | Platform Lead + внешние эксперты | Все участники прошли DDD/Event Storming      |
| **Event Storming сессии**          | Data Architect                   | Модель событий для пилотных доменов          |
| **Разработка событий**             | Data Engineer домена             | Код продюсеров событий                       |
| **Создание первой витрины**        | BI Analyst                       | Дашборд в Power BI на событиях               |
| **Демо руководству**               | Data Product Owner               | Презентация успехов                          |

**Риски этапа**

| Риск                          | Вероятность | Митигация                               |
|-------------------------------|-------------|-----------------------------------------|
| Команды не понимают Data Mesh | Высокая     | Интенсивное обучение, внешние эксперты  |
| Технические сложности с Kafka | Средняя     | Привлечение эксперта по Kafka           |
| Пилотные домены не готовы     | Низкая      | Тщательный отбор, поддержка руководства |
| Отсутствие быстрых побед      | Средняя     | Выбор простых первых событий            |

## 4. Этап 2: Масштабирование (6-18 месяцев)

**Цели этапа**

| Цель                              | Критерий успеха                           | Срок     |
|-----------------------------------|-------------------------------------------|----------|
| Подключить все критические домены | 7-8 доменов публикуют события             | Месяц 12 |
| Запустить кросс-доменные отчеты   | 5+ отчетов, объединяющих 3+ домена        | Месяц 14 |
| Внедрить Data Catalog             | Каталог содержит все домены               | Месяц 15 |
| Запустить потоковые витрины       | 3+ near-real-time дашборда                | Месяц 16 |
| Начать миграцию из DWH            | 30% отчетов переведено на новую платформу | Месяц 18 |

**Домены для масштабирования**

| Приоритет | Домен                       | Data Product Owner   | Сложность | Зависимости       |
|-----------|-----------------------------|----------------------|-----------|-------------------|
| 1         | **EMR (Медицинская карта)** | Главврач             | Высокая   | Пациентский поток |
| 2         | **Fintech (Банк)**          | Руководитель финтеха | Высокая   | Пациент           |
| 3         | **Инвентаризация**          | Технический директор | Средняя   | -                 |
| 4         | **Персонал (HR)**           | HR-директор          | Низкая    | -                 |
| 5         | **ИИ-сервисы**              | Руководитель ИИ      | Средняя   | EMR, Диагностика  |
| 6         | **Диагностика**             | Зав. отделением      | Высокая   | EMR               |

**Ключевые активности**

| Активность                            | Ответственный                  | Результат                                          |
|---------------------------------------|--------------------------------|----------------------------------------------------|
| **Формирование команд доменов**       | Руководители направлений       | Data Product Owner + Data Engineer в каждом домене |
| **Event Storming для каждого домена** | Data Architect + Domain Expert | Модели событий утверждены                          |
| **Разработка событий (параллельно)**  | Data Engineer доменов          | 20+ событий в каждом домене                        |
| **Интеграция Data Catalog**           | Platform Team                  | Все события документированы, поиск работает        |
| **Создание антикоррупционного слоя**  | Platform Team + Legacy Team    | Двусторонняя синхронизация с DWH                   |
| **Разработка кросс-доменных отчетов** | BI Analyst                     | Единые дашборды по KPI                             |
| **Обучение новых команд**             | Platform Lead                  | Стандарты внедрены                                 |

**Риски этапа**

| Риск                             | Вероятность | Митигация                                           |
|----------------------------------|-------------|-----------------------------------------------------|
| Перегрузка платформенной команды | Высокая     | Увеличение платформенной команды                    |
| Несогласованность схем событий   | Средняя     | Schema Registry, архитектурные ревью                |
| Сопротивление доменов            | Высокая     | Демонстрация успехов пилотов, поддержка руководства |
| Задержки в миграции из DWH       | Средняя     | Приоритизация отчетов, автоматизация                |

## 5. Этап 3: Целевое состояние (18-36 месяцев)

**Цели этапа**

| Цель                          | Критерий успеха                         | Срок     |
|-------------------------------|-----------------------------------------|----------|
| Полный отказ от DWH           | DWH выведен из эксплуатации             | Месяц 24 |
| Все домены работают событийно | 10+ доменов, все события в Kafka        | Месяц 24 |
| Географическая экспансия      | 2 новых региона со своими доменами      | Месяц 30 |
| Монетизация данных            | 3+ партнера используют данные через API | Месяц 30 |
| Self-service BI               | 80% отчетов создается пользователями    | Месяц 36 |

**Ключевые активности**

| Активность                          | Ответственный                      | Результат                                    |
|-------------------------------------|------------------------------------|----------------------------------------------|
| **Отключение DWH**                  | Platform Team + Legacy Team        | DWH остановлен, все данные в Data Mesh       |
| **Запуск федеративного управления** | Governance Lead                    | Политики доступа, compliance автоматизирован |
| **Создание региональных доменов**   | Platform Team + Regional Teams     | Локальные домены с синхронизацией            |
| **Разработка API для партнеров**    | AI Services Domain + Platform Team | Партнерский портал, биллинг по использованию |
| **Внедрение ML Platform**           | AI Services Domain                 | Feature Store, Model Monitoring              |
| **Оптимизация затрат**              | Platform Team                      | FinOps практики, автоскейлинг                |

**Риски этапа**

| Риск                                     | Вероятность | Митигация                                |
|------------------------------------------|-------------|------------------------------------------|
| Сложность управления 10+ доменами        | Средняя     | Зрелые процессы, автоматизация           |
| Регуляторные требования в новых регионах | Высокая     | Юридический анализ, локальный compliance |
| Рост затрат на облако                    | Средняя     | FinOps, оптимизация хранения             |
| Уход ключевых сотрудников                | Средняя     | Документирование, кросс-тренинг          |
